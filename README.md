# ThoraxAI - Система анализа КТ органов грудной клетки

## Описание

ThoraxAI - это система автоматического анализа компьютерных томографий органов грудной клетки с использованием искусственного интеллекта. Основная цель системы - обнаружение патологий в КТ исследованиях с использованием модели Swin Transformer

## Основные возможности

- **Автоматическая классификация КТ исследований** на два класса: «без патологии» и «с патологией»
- **Параллельная обработка** - несколько исследований обрабатываются одновременно
- **Отслеживание прогресса в реальном времени** - статус обработки каждого файла с возможностью отмены
- **Корректная обработка DICOM файлов** из ZIP архивов с поддержкой различных структур
- **Современный веб-интерфейс** для загрузки и просмотра результатов с темной темой
- **Генерация отчетов** в формате Excel с детальной статистикой
- **Визуализация патологий** с возможностью скачивания изображений и DICOM файлов
- **Управление файлами** с возможностью массовой очистки
- **Детальная статистика** батчей с временем обработки

## Архитектура системы

### Компоненты

1. **Основной сервис (FastAPI)** - веб-приложение и REST API
2. **ML сервис** - сервис машинного обучения на основе Swin Transformer
3. **База данных PostgreSQL** - хранение метаданных и результатов
4. **Redis** - брокер сообщений и бэкенд результатов для Celery
5. **Celery Worker** - асинхронная обработка исследований
6. **Файловое хранилище** - DICOM файлы и извлеченные изображения

### ML Модель

#### Архитектура
- **Модель**: Fine-tuned Swin Base Transformer
- **Конфигурация**: размер патча 4×4 с окном для self-attention 7×7 (`swin_base_patch4_window7_224`)
- **Классы**: 2 (норма, патология)

#### Работа с данными
- **Патологии**: исследования более 44 различных патологий органов грудной клетки
- **Контрасты**: снимки сохранены в 3 разных контрастах
  - Мягкотканный контраст
  - Костный контраст
  - Легочный контраст
  - С соответствующими значениями WW (Window Width) и WL (Window Level)
- **Фильтрация**: функции для сохранения только тех снимков, которые содержат патологии при работе с датасетом
- **Датасет после аугментации**:
  - 62,433 снимка без патологий
  - 122,786 снимков с патологиями

#### Метрики качества
- **ROC AUC**: **0.995**
- **F1 Score**: **0.999**
- **Тестирование**: метрики подсчитаны на основе теста на 36,000+ изображений с соотношением классов 32-68
- **Статистика**: байесовская вероятность и 95% доверительный интервал для определения вероятностей

### Алгоритм анализа

1. **Извлечение изображений** из DICOM файлов с применением различных контрастов по WW WL
2. **Предсказание на уровне кадров** с порогом вероятности 0.6
3. **Агрегация на уровне исследования** с минимальной долей положительных кадров 12%
4. **Доверительные интервалы** для статистической надежности

### Процесс асинхронной обработки

1. **Загрузка файлов** - пользователь загружает до 400 ZIP файлов через веб-интерфейс
2. **Создание задач** - каждый файл становится отдельной задачей Celery
3. **Постановка в очередь** - задачи помещаются в Redis и распределяются между воркерами
4. **Параллельная обработка** - воркеры обрабатывают исследования одновременно
5. **Отслеживание прогресса** - веб-интерфейс показывает статус каждой задачи в реальном времени
6. **Завершение** - результаты сохраняются в БД, генерируется Excel отчет

### Запуск с CPU

Для запуска на CPU необходимо внести изменения в `docker-compose.yml`:

1. Удалите строку `runtime: nvidia` из сервиса `ml-service`
2. Измените переменную окружения `DEVICE=cuda` на `DEVICE=cpu`

Также в `ml-service/Dockerfile` замените установку PyTorch на CPU версию:

```dockerfile
FROM ubuntu:22.04

# ... остальные инструкции ...

RUN python3.10 -m pip install --no-cache-dir \
    torch==2.1.0 \
    torchvision==0.16.0 \
    torchaudio==2.1.0 \
    --index-url https://download.pytorch.org/whl/cpu
```

## Использование

### Веб-интерфейс

1. **Откройте браузер** и перейдите по адресу `http://localhost:8000`
2. **Загрузите файлы** - выберите до 400 ZIP архивов с DICOM исследованиями
3. **Отслеживайте прогресс** - прогресс-бар покажет состояние обработки каждого файла в реальном времени
4. **Просмотрите результаты** - после завершения нажмите "Посмотреть результаты" или перейдите в "Загрузки"
5. **Скачайте отчет** - Excel файл с полной статистикой доступен в разделе "Загрузки"

#### Доступные страницы

- **Главная** (`/`) - загрузка новых исследований с отслеживанием прогресса
- **Исследования** (`/studies`) - просмотр всех исследований с фильтрацией
- **Загрузки** (`/batches`) - история батчей с временем обработки и **скачиванием Excel отчетов**
- **Детали батча** (`/batches/{id}`) - подробная информация о батче, статус задач, возможность отмены
- **Файлы** (`/cleanup`) - управление файлами, массовая очистка, проверка активных задач

#### Особенности интерфейса

- **Реальное время** - статус обработки обновляется каждые 2-3 секунды
- **Отмена обработки** - можно отменить батч во время обработки
- **Время обработки** - отображается для каждого батча
- **Статус задач** - детальная информация о каждой задаче в батче
- **Темная тема**

> **📊 Важно**: Итоговые Excel отчеты с результатами анализа скачиваются в разделе **"Загрузки"** (`/batches`). Это основной результат работы системы согласно ТЗ

## Формат выходных данных

Система генерирует Excel отчеты со следующими колонками:

| Колонка | Описание | Формат |
|---------|----------|--------|
| `path_to_study` | Путь к исследованию | String |
| `study_uid` | Идентификатор исследования (DICOM) | String |
| `series_uid` | Идентификатор серии (DICOM) | String |
| `probability_of_pathology` | Вероятность патологии (0.0-1.0) | Float |
| `pathology` | Норма/патология (0/1) | Integer |
| `processing_status` | Статус обработки | String |
| `time_of_processing` | Время обработки (секунды) | Float |
| `ci_95` | Предельные вероятности для 95% доверительного интервала | Object |

## Производительность

### GPU версия (рекомендуется)
- **Время обработки**: ~2-3 минуты на исследование
- **Параллельная обработка**: 4 исследования одновременно (по умолчанию)
- **Максимальный размер файла**: 2GB
- **Максимальное количество файлов**: 400 за раз

### CPU версия
- **Время обработки**: ~10 минут на исследование (в несколько раз медленнее GPU)
- **Максимальный размер файла**: 2GB
- **Максимальное количество файлов**: 400 за раз
- **Требования к памяти**: 16GB+ RAM (CPU версия требует больше памяти)

### Настройка параллелизма

Количество воркеров настраивается в `docker-compose.yml`:

```yaml
celery-worker:
  command: celery -A app.core.celery_app worker --loglevel=info --concurrency=4
  # Для CPU рекомендуется --concurrency=2
```

## Технические особенности

### Обработка данных
- **Автоматическое определение оптимальной серии** для анализа
- **Поддержка multi-frame DICOM** файлов
- **Статистический анализ** с доверительными интервалами Wilson Score
- **Работа со временем** - все временные метки в UTC+3

### Архитектура
- **Асинхронная обработка** через Celery + Redis
- **Параллельное выполнение** - несколько воркеров одновременно
- **Масштабируемость** - возможность добавления воркеров
- **Отказоустойчивость** - retry механизм для задач

### Управление
- **Отслеживание активных загрузок** для предотвращения конфликтов
- **Управление файлами** с возможностью массовой очистки
- **Мониторинг задач** - детальная информация о каждой задаче
- **Отмена обработки** - возможность остановить батч
